# Порция — Telegram-бот баланса питания

Первая версия для личного использования: постепенное снижение веса с акцентом на состав еды и сытость. Работает на Python 3.9+ без сторонних библиотек. Код подготовлен; для настоящего запуска нужны токен Telegram, ключ OpenAI API и постоянно работающий компьютер или сервер.

## Что умеет

- Анкета: возраст, вариант формулы обмена, рост, вес, повседневная активность без тренировок, индивидуальные ограничения, необязательная ширина ладони, часовой пояс.
- Анализ фото с ладонью, подписи или текстового описания. Предполагаемый состав, масса с диапазоном неопределённости, БЖУ и энергия.
- Уточнения обычным сообщением до сохранения: «это индейка», «гречки 120 г в готовом виде», «масла 5 г». При уточнении весь черновик пересчитывается.
- Подтверждение порции перед добавлением в дневник; несколько фото не превращаются в дубликаты автоматически.
- Кнопки **Наелась / Не наелась / Проголодалась / Вкусно / Не вкусно** после каждого сохранённого приёма. Сытость и вкус — независимые отметки. Повторный голод не меняет первую отметку времени.
- Дневной баланс БЖУ и мягкие рекомендации; дневник показывает вкус и интервал до голода.
- Отдельная тренировка на текущий день с пересчётом ориентира; повторный ввод заменяет тренировку, не удваивает её.
- SQLite сохраняет анкету, черновики, приёмы и отметки после перезапуска.
- Личный доступ по списку Telegram ID; работа только в личной переписке; удаление отдельной записи и всей активной истории.

## Запуск на Mac

1. В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, выбери имя и username. Сохрани выданный токен локально, не публикуй его.
2. Создай ключ в [OpenAI API](https://platform.openai.com/api-keys). Анализ использует отдельный API-доступ и его тарификацию. У аккаунта должен быть доступ к выбранной модели; подписка на приложение сама по себе здесь не проверяется и не используется.
3. Узнай свой числовой Telegram user ID. Его можно посмотреть в экспортированных данных Telegram Desktop (Настройки → Продвинутые настройки → Экспорт данных Telegram → JSON; поле `personal_information.user_id`). Username вида `@name` не подходит.
4. В Терминале открой эту папку и запусти:

```sh
python3 setup.py
python3 bot.py
```

Настройщик скрывает ввод ключей, сохраняет `.env` с правами `600` и не перезаписывает существующий файл. Можно вместо него заполнить `.env` по `.env.example` в локальном редакторе. Не вставляй ключи в переписку, GitHub или команды, попадающие в историю терминала.

5. Открой созданного бота, нажми `/start`, ознакомься с обработкой данных и заполни анкету.

Пока Mac включён, не спит и `bot.py` работает, бот принимает сообщения. Для круглосуточной работы нужен отдельный сервер с постоянным диском; в этой версии сервер не развёрнут. Запускай только один экземпляр с одной базой. Для контейнера обеспечь постоянный том на `/app/data`; пример есть в `Dockerfile`.

## Пример сценария

1. Фото обеда с ладонью и подписью: «гречка, индейка, салат, заправка — масло».
2. Бот выдаёт оценку состава и массы. Уточнение: «индейки 130 г, масла 5 г».
3. При необходимости `/time 13:20` — время сегодняшнего приёма (по умолчанию время отправки фото).
4. **Сохранить порцию**, затем **Наелась** и **Вкусно**.
5. Когда снова захочется есть — **Проголодалась**. Если уже был новый приём пищи, отметка относится к нему; старую кнопку бот отклонит.
6. `/today` — дневник и баланс. `/workout` → `средняя 45` или `нет`.

## Как устроены оценки

**Фото не заменяет весы.** Даже ладонь известной ширины не определяет плотность еды, высоту порции, перспективу, масло или скрытые ингредиенты. Диапазон массы — предположение модели, а не измеренная точность. БЖУ тоже приблизительны; источник — модель, а не проверенная продуктовая база. Перед сохранением пользователь подтверждает или исправляет состав. Для точной записи используй весы и данные упаковки в описании.

Энергия рассчитывается из БЖУ по 4/9/4 ккал на грамм. Это упрощение не учитывает отдельно алкоголь, сахарные спирты и особенности клетчатки; точные значения на этикетке могут отличаться. Автоматической оценки витаминов, минералов и дефицитов нет.

Расчёт обычного дня: Mifflin–St Jeor × ориентировочный коэффициент бытовой активности (1.2 / 1.375 / 1.55), затем начальный дефицит 10%. Это прозрачные проектные настройки первой версии, не индивидуальное медицинское назначение и не гарантия темпа похудения. Защитная нижняя граница 1200/1500 ккал по варианту формулы не означает, что такой рацион подходит конкретному человеку. При возрасте до 18 лет, BMI ниже 18.5 или указанном индивидуальном плане автоматический ориентир отключён; дневник доступен.

Тренировка: приблизительные категории 3/5/7 MET; добавка `(MET − 1) × вес × часы × 0.9`. Это грубая оценка, не показания прибора. В отдых добавки нет, дополнительных вычетов нет. В анкете тренировки исключены из бытовой активности. Одна запись тренировки за день; несколько сессий пока нужно объединять вручную по длительности и подходящей интенсивности.

Ориентир БЖУ: 20/30/50% энергии. Сигналы о долях используют широкие взрослые диапазоны: белок 10–35%, жиры 20–35%, углеводы 45–65%. Это не персональные нормы граммов. По отдельному приёму и неполному дню нельзя диагностировать недостаток нутриентов. Рекомендации касаются записанной еды и не предлагают пропускать еду или компенсировать её тренировками.

Отсчёт до голода начинается от времени приёма, не от нажатия «Наелась». Это время до нажатия кнопки, а не объективное измерение насыщения; забытые перекусы и поздние отметки влияют на результат.

## Данные и ограничения

Фото скачивается в память, передаётся OpenAI как base64 и не записывается на диск. Для повторной оценки незавершённого черновика сохраняется Telegram file ID. После подтверждения остаётся только структурированная оценка. Анкета не передаётся модели, кроме необязательной ширины ладони. У Responses API задано `store=false`; это не исключает служебное хранение по политике провайдера. Telegram сохраняет переписку отдельно.

Файлы `.env` и `data/` исключены из Git. `/delete` очищает активную SQLite-базу логически, но не стирает сообщения Telegram, внешние журналы, резервные копии или форензические следы SQLite. Доступ к компьютеру и резервным копиям остаётся ответственностью владельца. База не зашифрована.

Первая версия обрабатывает запросы последовательно. Нет фоновых напоминаний, автоматического изменения цели по динамике веса, распознавания медицинских состояний, сервера и промышленной очереди. При сбое сервиса черновик сохраняется; уточнение повторяет анализ. При падении между записью и отправкой сообщения возможна потеря уведомления, но сохранённую еду можно увидеть через `/today`.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют расчёты, временные границы суток, владельца записей, подтверждение и дубликаты, повторные отметки голода, восстановление состояния, отключение цели, удаление и контракт API. Сетевые ответы заменены тестовыми. Реальные Telegram/OpenAI вызовы и точность по настоящим фото требуют ключей и ручного приёмочного прогона.
